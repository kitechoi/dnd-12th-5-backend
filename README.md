## 📝 프로젝트 소개
<img width="1920" alt="KakaoTalk_Photo_2025-03-15-13-21-31 006" src="https://github.com/user-attachments/assets/42f01b0a-8cc8-4c46-a3e3-24d7d8433b74" />

<br>

**PICKTORY**는 **선물 후보에 대한 상대방의 생각을 확인할 수 있는 서비스**입니다.

- 사용자는 **선물 보따리**를 만들어 선물 후보(2~6개)와 메시지를 기록할 수 있습니다.
- 보따리는 **임시저장 또는 바로 생성**이 가능하며, 링크를 통해 공유할 수 있습니다.
- 링크를 받은 상대방은 **선물 후보를 확인하고 응답**을 남길 수 있습니다.
- 응답을 통해 선물 고민의 과정을 줄이고, 더 좋은 선물을 선택할 수 있습니다.

## 🤔 기술적 이슈와 해결 과정

### **1. 트랜잭션 정합성 유지 및 REST API 트레이드오프**
- 보따리, 선물, 선물 이미지를 개별 API로 처리하면 **네트워크 요청 증가 및 트랜잭션 관리 복잡성** 발생.
- REST 원칙을 일부 포기하고 **한 번의 요청에서 보따리, 선물, 선물 이미지를 순차적으로 트랜잭션 처리**.
- **결과:** API 호출 최소화 + 데이터 정합성 보장.

### **2. Batch Insert를 활용한 4배 성능 개선**
- `JPA saveAll()`이 개별 INSERT 실행 → 성능 저하 발생 가능.
- **JdbcTemplate `batchUpdate()` 활용하여 Batch Insert 실험 → 4배 성능 개선 가능성 확인.**
- 현재 서비스 규모에서는 필요성 낮아 **향후 확장성을 고려한 옵션으로 유지.**
   - 👉🏻 [Batch Insert 고민 과정 보기](https://velog.io/@whyceline/JPA-vs-JdbcTemplate-Batch-Insert-4%EB%B0%B0-%EB%B9%A0%EB%A5%B8-%EC%86%8D%EB%8F%84-%ED%95%98%EC%A7%80%EB%A7%8C-%EC%B5%9C%EC%A0%81%ED%99%94%EA%B0%80-%EC%A0%95%EB%8B%B5%EC%9D%BC%EA%B9%8C)
